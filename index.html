ARTEVIVA y ARTEVIVAX: manuales y guía técnica

Dos productos en un mismo servidor: la plataforma de aprendizaje de danza con IA (/app y app móvil) y el streaming de clases por suscripción (/streaming). Esta guía describe lo que existe hoy y marca sin rodeos lo que falta.

Equipo técnico

Cómo está armado

Una sola instancia EC2 atiende los dos productos. El nginx del servidor reparte por ruta; dentro de /app un segundo nginx (el gateway) enruta a los servicios.

Despliegue

flowchart TB
  A[git push a trunk] --> B[Runner en la EC2]
  B --> C[Restaura secretos de ~/secrets]
  C --> D[Detecta servicios cambiados]
  D --> E[Construye solo lo cambiado]
  E --> F[podman-compose up -d]
  F --> G[Reinicia gateway]
  G --> H[Verifica salud]
El job define RUNNER_TRACKING_ID: "". Sin eso, el runner mata al terminar el DNS interno de Podman y el puerto 8080, y la plataforma queda caída tras cada despliegue. No se debe quitar.
Manual 1 · Web

Administrador: cargar el catálogo

Un curso es un “mundo” de danza. Cada curso tiene lecciones y cada lección lleva un video MP4, un esqueleto JSON (poses de referencia para la IA) y una miniatura JPEG. Solo lo Publicado lo ven los estudiantes.

flowchart LR
  A[Crear curso] --> B[Crear lecciones]
  B --> C[Subir video, esqueleto y miniatura]
  C --> D[Revisar lecciones]
  D --> E[Publicar el curso]

Entrar y reconocer el panel

  1. Abre https://www.artevivax.com/app/login, escribe correo y contraseña y pulsa Ingresar.
  2. Con rol ADMIN o TEACHER llegas al Panel de Administración. La sesión se renueva sola; si te lleva al login, entra de nuevo.

Crear una lección y subir sus archivos

  1. Lecciones → Nueva Lección (o + Lección en la fila del curso). Completa curso, título, slug único, nivel, orden, duración en segundos, BPM (40 a 220) y puntos de recompensa.
  2. Panel → Subir Media: elige la lección, el tipo (.mp4, .json o JPEG), el archivo, y pulsa Subir. Al terminar, la lección queda vinculada sola.
  3. En Cursos pulsa Publicar. Antes, revisa que el curso tenga al menos una lección con video y esqueleto.

Manual 2 · Web

Padres, madres, acudientes y docentes

Estado actual. Funcionan el registro, el inicio de sesión y la portada del panel. Hijos, Consentimientos y Progreso tienen su lógica en el servidor pero sus pantallas no están construidas: esos enlaces llevan a una página sin contenido (404).

  R --> P
  D[Docente · web] -->|resultados de su curso| R
  A[Administrador] -->|carga cursos| C[Catálogo]

Crear cuenta e ingresar

  1. En /app/register completa nombre, apellido, correo y contraseña (mínimo 8, con mayúscula, minúscula, número y un símbolo de @ $ ! % * ? &). En Soy… elige Padre/Madre/Tutor o Profesor/a.
  2. La cuenta queda pendiente de verificación. El correo de verificación está desactivado, así que el equipo técnico debe activarla (ver Operación).
  3. Con la cuenta activa, entra por /app/login. Para salir pulsa Salir.

Manual 3 · App móvil

Estudiante: practicar con la cámara

Abres una práctica, apoyas el celular frente a ti y bailas. Cada dos segundos la app envía una imagen a la IA, que compara tu postura con la del profesor y te muestra puntaje, carita de ánimo y una sugerencia.

flowchart LR
  Cam[Cámara] -->|imagen cada 2 s| API[ARTEVIVA]
  API --> Pose[Detecta postura]
  API --> Emo[Detecta ánimo]
  Pose --> Cmp[Compara con el profesor]
  Cmp --> Out[Puntaje + sugerencia]
  Emo --> Out
  Out --> Pantalla[Tu pantalla]

Instalar

Android: abre arteviva.apk, permite instalar desde esa fuente si Android lo pide, pulsa Instalar y Abrir. iPhone: aún no disponible (requiere cuenta Apple Developer de pago).

Manual 5 · Equipo técnico

Operación diaria

DatoValor
ServidorEC2 ip-172-31-33-17, x86_64, Ubuntu · IP 54.162.68.97 (confirmar Elastic IP)
ContenedoresPodman rootless + podman-compose, ~25, archivo docker-compose.prod.yml
Secretos~/secrets/services/<servicio>.env.prod (fuera del repo; sin copia externa)
nginx del host/streaming/ → 4000 · /app/ → 8080. Copia en deploy/nginx-artevivax-domain.conf
SesiónJWT de 15 min (HS256, mismo JWT_SECRET). Roles: SUPER_ADMIN, ADMIN, TEACHER, PARENT, STUDENT
Comprobar que todo vive (web = 200, login falso = 401)
podman ps --format '{{.Names}}\t{{.Status}}'
curl -s -o /dev/null -w '%{http_code}\n' https://www.artevivax.com/app/
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://www.artevivax.com/app/api/auth/login -H 'Content-Type: application/json' -d '{"email":"x@x.com","password":"x"}'
502 o login con error 500 sin logs: reiniciar el gateway (no usar podman restart con los de la app)
podman stop arteviva-nginx; podman start arteviva-nginx
Logs de un servicio
podman logs --tail 100 arteviva-identity
podman logs --tail 100 arteviva-admin
Entrar a la base de identidad
PG=$(podman ps --format '{{.Names}}' | grep -i -E 'pg|postgres' | grep -i identity | head -1)
podman exec -it $PG sh -c 'psql -U "$POSTGRES_USER" -d identity_db'
Activar una cuenta registrada (SQL)
UPDATE users SET status='ACTIVE', email_verified_at=NOW() WHERE email='correo@dominio.com';
Cambiar rol (SQL)
UPDATE users SET role='ADMIN' WHERE email='correo@dominio.com';
Crear un estudiante (el registro público no lo permite)
H=$(podman exec arteviva-identity node -e "console.log(require('bcryptjs').hashSync(process.argv[1],12))" 'LaContraseñaNueva1@')
podman exec -i $PG sh -c 'psql -U "$POSTGRES_USER" -d identity_db' <<SQL
INSERT INTO users (email,password_hash,first_name,last_name,role,status,email_verified_at)
VALUES ('estudiante@dominio.com','$H','Nombre','Apellido','STUDENT','ACTIVE',NOW());
SQL

Compilar el APK (desde una copia fuera del monorepo)
cp -R apps/mobile ~/arteviva-mobile && cd ~/arteviva-mobile
npm install
npx expo install expo-constants expo-linking expo-status-bar react-native react-native-safe-area-context react-native-screens

Seguridad antes de entregar

  1. Revocar todos los tokens de GitHub creados durante el montaje y cualquier credencial que haya circulado en chats o correos.
  2. Cambiar las contraseñas de las cuentas de prueba (administrador y estudiante).
  3. Guardar una copia cifrada de ~/secrets fuera del servidor.
  4. Asignar una Elastic IP, programar pg_dump hacia S3 y apagar la instancia ARM anterior tras 2 o 3 días estables.
